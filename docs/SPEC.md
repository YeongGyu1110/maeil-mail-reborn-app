# 매일메일 앱 기획

웹 서비스 [maeil-mail-reborn](https://github.com/YeongGyu1110/maeil-mail-reborn)과 같은 질문, 같은 학습 기록을 쓰는 개인용 안드로이드 앱이다.
메일을 받고 답안을 보러 브라우저를 여는 불편을 없애는 것이 목적이다. 알림을 누르면 앱에서 바로 답안을 본다.

## 전체 구조

| 무엇 | 어디에 | 누가 쓰나 |
|---|---|---|
| 질문 목록과 답안 (마크다운) | 웹 저장소 `master` 브랜치 | 사람이 직접 추가. 앱과 웹은 읽기만 |
| 오늘·앞으로 받을 질문 | 웹 저장소 `progress.json` | GitHub Actions만 씀. 앱과 웹은 읽기만 |
| 메일 발송 | GitHub Actions + Gmail | 지금처럼 유지 |
| 학습 수준, 별표, 메모 | Firestore `users/{uid}` | 웹과 앱이 함께 읽고 씀 |
| 메모 커밋 (잔디) | 내가 고른 메모 저장소 | 웹과 앱이 각자 커밋 |

## 1. 오늘의 질문

### 질문을 미리 정해 둔다
GitHub Actions의 예약 실행은 05:07로 잡아도 실제로는 3~6시간 늦게 돈다. 그래서 질문을 **보내는 순간에 고르지 않고, 앞으로 받을 3일치를 미리 정해 둔다.** 앱은 미리 정해진 질문으로 정확한 시각에 알림을 띄운다.

### `progress.json` 형식

```json
{
  "sent": ["fe-1", "fe-5", "...", "fe-77"],
  "today": { "date": "2026-11-17", "id": "fe-77" },
  "next": {
    "2026-11-18": "be-22",
    "2026-11-19": "fe-131",
    "2026-11-20": "fe-40"
  }
}
```

- `sent`: 지금까지 보낸 질문 ID. 보낸 순서대로. 지금 형식 그대로 유지하고 날짜는 남기지 않는다.
- `today`: 가장 최근에 보낸 질문과 그 발송일. 보낼 때 `next`에서 옮겨 온다. 웹이 "오늘 받은 질문"을 찾는 데 쓴다.
- `next`: 앞으로 받을 **메일 발송일 3일치**. 키는 한국 시간 날짜(`YYYY-MM-DD`), 값은 질문 ID.
  - 발송하지 않는 요일은 건너뛴다. 예: 평일만 받으면 금요일 실행 뒤 `next`는 월·화·수.

### Actions가 실행될 때마다 하는 일
날짜는 모두 **한국 시간** 기준이다. Actions는 UTC로 돌기 때문에 꼭 변환한다.

1. `next`에서 오늘 날짜 질문을 메일로 보낸다. 보낸 질문은 `today`로 옮기고(날짜와 ID), `sent` 끝에 ID를 추가한다.
   - 실행이 빠져서 지난 날짜 질문이 남아 있으면 그것도 날짜 순서대로 함께 보내고 옮긴다. 앱 알림으로 받은 질문이 Gmail에도 남도록. `today`에는 마지막으로 보낸 것이 남는다.
   - 오늘이 발송일이 아니면 보내지 않는다.
2. `next`의 빈 날짜를 채워 3개로 만든다.
   - **한 번 정한 질문은 보낼 때까지 바꾸지 않는다.** 앱이 `next`를 보고 알림을 미리 예약하므로, 바꾸면 알림과 메일이 어긋난다.
   - 그래서 쉬는 날 실행에서는 아무것도 바뀌지 않고 커밋도 생기지 않는다.
3. 뽑는 규칙은 예전과 같다: `sent`와 `next`에 없는 질문 중 무작위. 프론트엔드와 백엔드가 모두 남아 있으면 백엔드 확률 20%.
4. 뽑을 질문이 없으면 다음 바퀴(처음부터 다시) 질문을 뽑는다. `sent`는 다음 바퀴 첫 질문을 실제로 보낼 때 비운다. 모든 질문이 바퀴마다 한 번씩 나온다.
5. 오늘이 발송일인데 `next`에 오늘이 없고 오늘 보낸 질문도 없으면 (새 방식 첫 실행, 발송 요일을 새로 늘린 날 등), 오늘 질문을 그 자리에서 뽑아 보낸다. 이런 날은 앱이 미리 알 수 없다.
6. 예약 실행이 같은 날 두 번 돌아도 오늘 질문은 이미 `next`에서 빠졌으므로 다시 보내지 않는다.
7. `next`에 있던 질문이 목차에서 빠지면 그 날짜에서 빼고 다른 질문으로 다시 채운다.
8. 목차에서 질문을 하나도 찾지 못한 영역이 있으면(목차 형식이 깨진 경우) `progress.json`을 건드리지 않고 멈춘다.

> 처음 기획에서는 다음 발송일만 고정하고 나머지는 매번 다시 뽑기로 했지만, 웹 저장소 `f7bcc1b`에서 위처럼 바꿨다.

### 수동 실행 (Actions 탭의 Run workflow)
수동 실행은 대부분 테스트용이고, 이때 온 메일은 잘 읽지 않고 지운다. 그래서 **수동 실행은 기록을 바꾸지 않는다.**

- 메일만 보내고 `progress.json`은 그대로 둔다. 같은 날 예약 실행이 돌면 그 질문을 다시 정상적으로 받는다.
- 보내는 질문: 오늘 질문이 있으면 그것(`next`의 오늘, 또는 `today`가 오늘이면 그것), 없으면(쉬는 날 등) 다음 발송일 질문.
- 메일 제목 앞에 `[테스트]`를 붙여 정기 메일과 구분한다.

### 발송 요일
- `daily-mail.yml`에 환경 변수로 적는다. 이 한 줄만 바꾸면 메일, 웹, 앱 모두에 적용된다.
  ```yaml
  MAIL_DAYS: mon,tue,wed,thu,fri   # 평일만
  ```
- 예약 실행(`cron`)은 매일 돌게 둔다. 발송일이 아닌 날엔 아무것도 보내지 않는다. 요일 판단은 `send_mail.py`가 한다.
- 앱과 웹은 요일 설정을 읽지 않는다. `next`에 날짜가 있으면 그날 질문이 있는 것이고, 없으면 쉬는 날이다.
- 요일을 바꿔도 `next`에 이미 정해 둔 날짜(최대 3번)는 예전 설정대로 보내고, 그 밖의 날짜부터 새 설정을 따른다.
  - 발송 요일을 늘리면 (예: 평일 → 매일), 늘어난 날(토·일)은 `next`가 이미 차 있어 미리 정해지지 않는다. 그날 실행이 그 자리에서 뽑아 보내므로 메일은 오지만, 앱 알림은 미리 예약되지 않는다.

### 웹의 "오늘 받은 질문"
- `next`에 오늘 날짜가 있으면 그 질문 (아직 발송 전).
- 없고 `today.date`가 오늘이면 `today.id` (오늘 이미 발송함).
- 둘 다 아니면 오늘은 쉬는 날이라 보여주지 않는다. 예: 토요일엔 `today`가 금요일이라 보이지 않는다.
- 앱의 홈 화면도 같은 규칙을 쓴다. 단, 알림 시각 전에는 보여주지 않는다.

## 2. 앱 알림

- 기본 시각은 **07:00**. 앱 설정에서 바꿀 수 있다.
- 정확한 시각에 울린다 (`USE_EXACT_ALARM`). 휴대폰을 껐다 켜도 다시 예약한다.
- 알림 내용은 `next`의 그날 질문 번호와 제목. 누르면 그 질문 화면이 열린다. 알림에 다른 버튼은 없다.
- 알림을 놓쳐도 다음 날은 새 질문을 준다. 쌓아 두지 않는다.
- `next`의 질문은 보낼 때까지 바뀌지 않으므로, 받아 둔 `progress.json`만으로 알릴 수 있다. 며칠 인터넷이 끊겨도 `next`에 있는 날까지는 알림이 제때 온다.
- 알람은 한 번에 하나만 건다: 받아 둔 기록(`next`와 오늘 보낸 `today`)에서 아직 알리지 않은 가장 가까운 발송일의 알림 시각. 울리면 다음 발송일을 다시 건다 (`reminder/Reminders.kt`).
- 같은 발송일은 한 번만 알린다. 휴대폰이 꺼져 있다가 알림 시각이 지나 켜졌으면, 그날 안에서는 바로 알린다.
- 메일이 먼저 나간 뒤(질문이 `today`로 옮겨진 뒤) 알림 시각을 늦추면, 그날 질문(`today`)으로 늦춘 시각에 알린다.
- 앱이 `progress.json`을 받는 때: 6시간마다(인터넷이 될 때, WorkManager), 알림이 울린 뒤, 앱을 열 때(30분이 지났거나 기록이 없으면). 받은 뒤 알람을 다시 건다.
  - `progress.json`은 질문 파일과 같은 방법으로 받는다 (커밋이 바뀌었을 때만, sha 대조).
- 알림 시각에 그날 질문을 받아 둔 기록에서 찾지 못하면 "오늘의 질문이 도착했어요"만 띄우고, 앱을 열면 받아 온다.
- 홈(오늘)은 알림 시각 전에는 그날 질문을 미리 보여주지 않는다 ("오늘의 질문은 07:00에 알려 드려요"). 쉬는 날에는 다음 발송일을 알려준다.
- 알림을 누르거나 홈에서 열면 이전·다음은 전체 목록 순서를 따른다.
- 설정의 "알림 미리 보기"는 다음 질문을 미리 알려주지 않도록 예시 질문(FE-1)으로 보여준다.
- 처음 열 때 알림 권한을 한 번 묻는다. 꺼져 있으면 홈과 설정에서 알리고, 다시 물을 수 없으면 이 앱의 알림 설정 화면을 연다.
- 설정에서 배터리 최적화 예외(제한 없음)를 요청할 수 있다. 삼성은 '사용하지 않는 앱'·'잠자는 앱' 목록도 확인하라고 안내한다.
- 기기: Galaxy A25 5G (SM-A256N), Android 16. 정확한 알람은 `USE_EXACT_ALARM`으로 설치할 때 허용된다 (2026-11-21 확인: 11/23 07:00에 오차 없이 걸림).

## 3. 질문 내용

- 웹 저장소 `master`에서 직접 읽는다: `frontend/toc.md`, `frontend/toc-category.md`, `frontend/contents/*.md`, 백엔드도 같은 구조.
- 질문 220개 본문을 다 합쳐도 약 0.6MB라서 **전부 기기에 저장해 두고**, 바뀐 파일만 새로 받는다. 인터넷이 없어도 모든 질문을 볼 수 있다.
- 맞추는 방법 (`data/ContentSync.kt`)
  - GitHub API로 기본 브랜치의 최신 커밋을 묻고, 지난번과 같으면 끝낸다. 다르면 그 커밋의 파일 목록(트리)을 받아, 받아 둔 파일과 git blob sha가 다른 것만 받는다.
  - 파일은 커밋을 고정한 raw 주소로 받아 CDN 캐시 때문에 옛 내용을 받지 않게 하고, 받은 내용의 sha를 트리와 대조한다. 저장소에서 없어진 파일은 지운다.
  - 받는 파일: 영역별 `toc.md`, `toc-category.md`, `contents/*.md`, `search-synonyms.js` (검색 동의어도 웹과 같은 파일을 쓴다).
  - 로그인 없이 GitHub API는 시간당 60번까지다 (한 번 맞출 때 2번). 한도에 걸리면 raw 주소로 목차와 아직 없는 답변만 받는다.
  - 앱을 열 때 마지막으로 맞춘 지 30분이 지났으면 맞춘다. 목록을 당기면 바로 맞춘다.
- 새 질문은 지금처럼 웹 저장소에 md를 추가하면 앱에 자동으로 반영된다.
- 질문 화면
  - 마크다운 본문, 코드 색칠, 코드 복사, 링크 열기
  - 이전·다음 질문으로 넘기기. 순서는 **보던 목록의 순서**(검색·필터 결과)를 따른다. 알림으로 바로 열었으면 전체 목록 순서.

## 4. 학습 기록과 메모 (웹과 동일)

- 웹과 같은 Firestore 문서를 함께 쓴다. 보안 규칙(`firestore.rules`)도 그대로다.
  ```
  users/{uid}            items:    { "fe-1": { level: "review" | "done", starred: true } }
                         memoRepo: { id, fullName: "owner/name" }
  users/{uid}/memos/{n}  { "fe-1": { memo: "...", memoAt: 1761379200000, memoUncommitted: true } }
  ```
  - `memoUncommitted`: 계정에는 저장했지만 GitHub에는 아직 올리지 않은 메모(임시저장, 커밋 실패)면 `true`, 아니면 필드가 없다. 계정에 남으므로 다른 기기에서도 "아직 올리지 않았어요"를 보여줄 수 있다.
  - 미학습은 `level`이 없다. 별표가 없으면 `starred`가 없다.
  - 메모는 묶음 문서 4개(`memos/0`~`memos/3`)에 나눠 담는다. 묶음 번호는 질문 번호 % 4 (`fe-17` → `memos/1`). 문서 하나의 최대 크기(1 MiB)를 메모가 다 쓰지 않게 하려는 것이다.
  - 메모를 지우면 묶음 문서에서 그 질문 항목째 지운다. 문서는 지우지 않는다(규칙상 삭제 불가).
  - 예전 형식(기본 문서 `items`에 `memo`, `memoAt`)이 남아 있으면 웹처럼 읽을 때 함께 읽고, `memoAt`이 더 최근인 쪽을 쓴다. 옮기기는 웹이 하므로 앱은 읽기만 해도 된다. 단, 그 메모를 앱에서 고치면 기본 문서의 예전 필드도 함께 지워, 나중에 되살아나지 않게 한다.
  - 수준·별표 변경과 메모 변경은 한 번의 batch 쓰기로 보낸다.
- 웹에서 바꾼 것은 앱에, 앱에서 바꾼 것은 웹에 보인다.
- 같은 메모를 다른 곳에서 바꿨는지 저장 직전에 확인한다 (웹 `questions/index.html`의 `confirmNoConflict`와 같게).
  - 편집기를 열 때의 메모를 기억해 둔다. 기록을 읽은 지 5분이 지났으면 저장 직전에 다시 읽는다.
  - 그사이 메모가 바뀌었으면 "다른 곳에서 이 메모가 바뀌었어요"라고 묻는다 (덮어쓰기 / 계속 쓰기). '계속 쓰기'를 고르면 덮어쓰기를 고를 때까지 저장할 때마다 다시 묻는다.
- 인터넷이 없을 때 바꾼 내용은 연결되면 저장하고 커밋한다. 잔디는 실제로 커밋된 날에 찍힌다.
- 앱의 이해도·별표 (3단계에서 만듦)
  - 웹처럼 바꾼 필드만 보낸다: Firestore REST `commit`에 `updateMask`로 `items.`fe-1`.level` 같은 경로를 넣는다. 미학습·별표 떼기는 필드를 지운다. 바꾼 뒤 0.6초 모았다가 한 번에 보낸다.
  - 마지막으로 읽은 기록은 기기에 두어 인터넷 없이도 보인다. 앱을 열 때 1분이 지났으면 다시 읽고, 질문 목록을 당겨도 다시 읽는다.
  - 보내지 못한 변경은 기기에 보관하고, 다시 읽어도 그 위에 덮는다 (이 기기에서 나중에 바꾼 것이 이긴다). 안드로이드는 뒤로 간 앱의 인터넷을 막으므로, 보내지 못하면 WorkManager 작업에 맡겨 인터넷이 될 때 보낸다.
  - 로그인하지 않으면 이해도·별표를 보이지 않는다 (웹처럼 이 기기에만 저장하는 방식은 두지 않는다).
- 메모 규칙은 웹과 같다.
  - 최대 3,000자. 편집기가 넣는 글(서식 버튼, 목록 이어 쓰기)도 넘기지 않는다.
  - 저장할 때 앞의 빈 줄과 끝의 공백만 걷어 낸다. 첫 줄의 들여쓰기는 그대로 둔다 (웹 `normalizeMemo`).
  - **저장**: 계정에 저장하고 메모 저장소의 기본 브랜치에 `{질문 ID}.md`로 커밋. 커밋 메시지 `메모 추가: FE-1 제목` / `메모 수정: FE-1 제목`. 내용이 그대로여도 아직 올리지 않은 메모면 커밋한다.
  - **임시저장**: 계정에만 저장하고 커밋하지 않는다. `memoUncommitted: true`로 표시하고 편집기는 열어 둔다. 휴대폰에서는 임시저장 버튼으로 한다 (웹도 터치 기기에서만 이 버튼을 보인다).
  - 아직 올리지 않은 메모는 "아직 GitHub에 올리지 않았어요 · 올리기"를 주황색으로 보여준다. 커밋에 실패한 메모도 같다.
  - **삭제**: 따로 삭제 버튼은 없다. 작성 칸을 비운 채 저장하면 지울지 묻고 지운다. 저장된 메모가 있는데 작성 칸을 다 비우면 안내 자리에 "비운 채 저장하면 메모를 지워요"를 빨간 글씨로 보인다.
  - 메모를 지우면 GitHub의 `{id}.md` 파일도 `메모 삭제: FE-1 제목` 커밋으로 지운다. 파일이 없으면(올린 적 없는 메모) 아무것도 하지 않고, 지우지 못하면 메모는 지운 채로 두고 알린다. 삭제 확인 창에 "저장소 파일도 지워지고 지난 커밋 기록은 남는다"고 적는다.
  - 메모는 마크다운이다. GitHub가 .md를 보여주는 방식(GFM, 한 줄 바꿈은 이어 붙임)으로 그린다. 메모 안의 HTML은 글자 그대로 보여주고, 링크는 http(s)·mailto·상대 경로만 연다.
  - 편집기는 작성 / 미리보기가 있다 (웹은 넓은 화면에서 나란히 보기도 있다). 서식 버튼, 목록 이어 쓰기, 들여쓰기·내어쓰기를 둔다.
  - 쓰던 내용은 저장하지 않아도 기기에 초안으로 자동 보관하고, 편집기를 다시 열면 "저장하지 않은 초안을 불러왔어요"와 함께 이어 쓴다. 초안은 기기에만 둔다 (웹도 브라우저에만 둔다).
  - 편집 중 나가거나 취소하면 쓰던 내용을 버릴지 묻는다.
  - 질문 화면에서 긴 메모는 접어 두고 "전체 보기 · 약 n줄 더"로 펼친다. 질문 목록에서는 마크다운 기호를 뺀 한 줄 미리보기만 보인다.
- 메모 저장소는 앱에서도 고르고 바꿀 수 있다. 설정은 Firestore `memoRepo` 하나를 함께 쓰므로, 앱에서 바꾸면 웹도, 웹에서 바꾸면 앱도 같이 바뀐다.
  - 고르는 목록은 GitHub App을 설치한 저장소 중 포크·보관 저장소를 뺀 것이다 (웹과 같다). 지금 고른 저장소는 번호(`id`)나 이름이 같으면 "선택됨"으로 보인다. 같은 이름으로 저장소를 다시 만들면 번호가 바뀌는데, 커밋은 이름으로 하므로 그대로 된다 (2026-11-22 기준 계정에 저장된 번호가 지금 저장소 번호와 다르다. 저장소를 다시 고르면 맞춰진다).
- 앱의 메모 (4단계에서 만듦)
  - 메모 보기와 편집기는 웹 파일을 그대로 옮겨 질문 화면의 WebView에서 돌린다 (`assets/viewer/memo-ui.js`, `memo.css`). 그래서 서식 버튼, 목록 이어 쓰기, 들여쓰기, 한글 입력 처리, 길면 접기가 웹과 같다. 웹에서 이 두 파일을 고치면 앱에도 옮긴다. `memo-ui.js`는 ES 모듈 대신 `window.MemoCore`(앱의 `memo-core.js`)에서 받도록만 바꿨다.
  - 화면 쪽 흐름(초안, 저장·임시저장·취소·삭제, 충돌 확인, 올리기)은 웹 `questions/index.html`의 코드를 `viewer.js`로 옮겼다. 저장·GitHub 커밋·확인 창은 앱(Kotlin)이 맡고, 본문 스크립트는 `MaeilApp.request`로 부탁한다.
  - 메모 묶음 문서는 컬렉션 목록 읽기 한 번으로 받는다. 메모와 이해도·별표를 바꾼 것은 한 번의 `commit`(여러 문서 쓰기)으로 보낸다.
  - 초안은 WebView의 저장소(localStorage)에 둔다. 메모를 쓰다가 뒤로 가거나 이전·다음 질문으로 넘기려 하면 버릴지 묻는다.
  - 화면 끝까지 그리므로 키보드가 올라와도 창이 줄지 않는다. 질문 화면을 키보드만큼 줄이고, 키보드가 떠 있는 동안은 이전·다음 막대를 숨긴다.
  - 저장 결과(커밋했어요, 올리지 못했어요 등)는 아래 알림(토스트)으로 보인다. 임시저장은 알리지 않고 편집기에 "임시저장됨 · 아직 커밋 전"으로 보인다.
  - 질문 목록 행에는 마크다운 기호를 뺀 메모 한 줄이 보이고, 검색은 메모 글도 찾는다 (웹과 같다).
  - 2026-11-22 확인: 새 메모 저장(커밋 "메모 추가"), 비운 채 저장해 삭제(커밋 "메모 삭제", 파일 지움), 임시저장(커밋 없음, "아직 GitHub에 올리지 않았어요 · 올리기"), 임시저장 메모 삭제(파일이 없어 커밋 없음), 쓰는 중 뒤로 가기 확인.

### 로그인
- 처음 한 번만 GitHub Device Flow로 로그인한다. 휴대폰에 나온 코드를 github.com에서 입력한다.
- 받은 갱신 토큰(refresh token)으로 GitHub 토큰을 **자동 갱신**한다. 다시 로그인하라는 화면이 뜨지 않게 한다. (GithubWidget과 같은 방식)
- 같은 GitHub 토큰으로 Firebase에 로그인해, 웹과 같은 계정(같은 `uid`)의 기록을 쓴다.
  - 로그인은 웹과 같은 GitHub App(`maeil-mail-reborn-memo`)으로 한다. 웹의 Firebase GitHub 로그인이 이 앱을 쓰므로, 같은 앱의 토큰이어야 메모 저장소 목록(`/user/installations`)과 커밋을 웹과 같은 권한으로 쓴다.
  - Firebase는 SDK 없이 REST로 쓴다 (로그인 `accounts:signInWithIdp`, 토큰 갱신 `securetoken`, 기록 `firestore.googleapis.com`). 키는 웹 `firebase-config.js`의 공개 웹 키를 그대로 쓴다. 브라우저 밖에서도 이 키가 받아지는 것을 확인했다 (2026-11-21). 그래서 Firebase 콘솔에 안드로이드 앱을 등록하지 않는다.
  - Firebase idToken은 1시간마다 갱신 토큰으로 새로 받는다.
  - 이 GitHub App은 사용자 토큰 만료를 쓰지 않는다 (로그인 응답에 만료 시각·갱신 토큰이 없다, 2026-11-22 확인). 그래서 토큰은 앱 권한을 취소하기 전까지 그대로 쓴다. 나중에 앱 설정에서 만료를 켜면, 만료 5분 전에 갱신 토큰으로 새로 받는 코드가 이미 있다.
  - 토큰은 앱 전용 저장소에 두고 기기 백업에서는 뺀다.
  - 안드로이드 16은 뒤로 간 앱의 인터넷을 막는다. 그래서 브라우저에서 승인하는 동안 생긴 연결 오류는 실패로 보지 않고 기다리며, 앱으로 돌아오면 바로 다시 묻는다.
- 미리 해야 할 일 (마침)
  - GitHub App `maeil-mail-reborn-memo` 설정에서 Device Flow 켜기
  - 그 앱의 Client ID를 앱 코드(`account/GitHubAuth.kt`)에 넣기. 비공개 앱이라 공개 API로는 읽을 수 없다.
- 2026-11-22 확인: Device Flow 토큰으로 Firebase에 들어가 웹과 같은 계정의 `users/{uid}`를 읽었다 (보안 규칙상 웹 주인 계정만 읽을 수 있다).

## 5. 화면

- 웹의 문서 보기 느낌을 따른다 (2026-11-21에 정함. 처음에는 배치를 웹과 다르게 하려 했으나, 둥근 모서리가 웹과 맞지 않아 바꿨다).
  - 색은 웹 `base.css`의 색 변수(라이트 `:root`, 다크 `[data-theme="dark"]`)를 그대로 옮긴다. 라이트 모드 글자색은 웹이 WCAG AA(4.5:1)에 맞춰 둔 값이다. 예: 초록 `--primary` 라이트 `#007d53` / 다크 `#00c47d`, 복습 필요 `--review` 라이트 `#a35c06`.
  - 웹의 좁은 화면(640px 이하) 배치를 따른다. 캔버스(`--bg-canvas`)는 책상, 지면(`--bg-paper`)은 문서다. 상단 바·필터·아래 탭은 캔버스에, 내용은 가장자리까지 닿는 지면에 둔다.
  - 상단 바는 웹처럼 경로로 보인다: "■ 매일메일 / 질문 목록", 질문 화면은 "← 질문 목록 / FE-1". 구분선은 긋지 않는다.
  - 모서리는 웹과 같다. 버튼·입력칸·메뉴·창·토스트 4dp, 작은 표시 2dp, 점 1dp. 알약·원 모양은 쓰지 않는다 (Material 스위치·시계판·새로고침 원·탭 표시를 각진 것으로 바꿨다).
  - 구분은 면보다 선으로 한다. 문서 머리 아래와 구분 제목 아래는 진한 선(`--rule-strong`), 행 사이는 옅은 선(`--rule`)이다. 누를 수 있는 행은 누를 때 글자보다 양옆 8dp 넓게 각진 바탕이 깔린다.
  - 글자 크기·굵기는 웹의 좁은 화면 값을 따른다 (문서 제목 23, 목록 제목 15, 분류·번호 12.5). 번호는 고정폭 글꼴 대신 숫자 폭을 맞춘 본문 글꼴로 쓴다. 아이콘은 웹과 같은 선 아이콘(Feather 모양)이다.
  - 버튼은 웹처럼 글자형이 기본이고, 옅은 면(`btn-soft`)과 초록 면(`btn-primary`)을 쓴다. 손가락으로 누르므로 높이만 40dp로 키웠다.
- 다크 모드는 휴대폰 설정을 따른다.
- 화면의 역할은 웹과 같게 나눈다.
  - 질문 목록은 질문을 찾아 고르는 화면이다. 학습 수준은 표시만 하고, 별표는 누를 수 있다. 행을 누르면 질문 화면으로 간다.
  - 질문 화면은 답변을 읽고, 이해도를 기록하고, 메모로 정리하는 화면이다.
- 화면 구성 (초안)
  - **홈**: 오늘의 질문 (이해도·메모 여부 함께), 학습 진행률
  - **질문 목록**: 검색 (웹과 같은 동의어 묶음), 카테고리·학습 수준·별표·**받은 질문** 필터. 번호순 목록에서는 백엔드가 시작하는 자리에 구분 제목을 둔다. 필터를 걸면 "220개 중 n개"와 필터 초기화를 보인다.
  - **질문 보기**: 영역·카테고리, 별표, 본문, 학습 기록(이해도, 메모), 이전·다음
  - **설정**: 알림 시각, 계정, 메모 저장소
- **진행률**은 메일로 받은 질문(`sent`와 오늘 질문) 가운데 '완벽 이해'의 비율로 센다. 아직 받지 않은 질문까지 세면 발송 일정만 보여주게 된다. `progress.json`을 못 읽으면 전체 질문으로 센다.
- **받은 질문** 필터를 켜면 받은 질문만 최근에 받은 순서로 보여준다 (`sent`를 거꾸로, 오늘 질문을 맨 앞에). 영역이 섞이므로 구분 제목은 감춘다.
  - 앱은 알림 시각 전에는 오늘 질문을 보여주지 않으므로, 오늘 질문은 알림 시각이 지난 뒤에만 받은 질문(필터와 진도)에 넣는다.
- 앱의 배치 (웹 좁은 화면과 같다)
  - 질문 목록: 캔버스에 학습 수준 네 칸(전체·미학습·복습 필요·완벽 이해, 고른 칸을 다시 누르면 전체), 받은 질문·별표 칸, 카테고리. 행 첫 줄에 번호, 학습 수준(미학습이면 없음), 별표 버튼.
  - 질문 화면: 상단 바 오른쪽에 별표, 본문 끝에 "학습 기록 · 이해도" 세 칸, 제목 아래에 지금 학습 수준.
  - 오늘: 문서 머리 아래에 학습 진도(받은 질문 중 완벽 이해 %, 초록·주황 막대). 오늘 질문 옆에 학습 수준.
- 동기화가 되지 않는 계정(소유자가 아닌 GitHub 계정)에게 로그인을 권하지 않는다. 앱은 소유자 혼자 쓰므로 크게 신경 쓸 일은 없다.

## 6. 2단계 (1차 버전 이후)

- 홈 화면 위젯: 오늘의 질문 번호와 제목, 누르면 열기 (5단계에서 만듦)
  - 오늘 탭과 같은 규칙: 알림 시각 전에는 "07:00에 알려 드려요"만, 쉬는 날이면 다음 질문 날짜, 알림 시각이 지나면 번호·제목·분류를 보인다. 질문이 보일 때 누르면 그 질문을, 아니면 앱을 연다.
  - 모양은 웹 문서 머리처럼: 지면색 바탕, "■ 오늘의 질문 · FE-1", 가는 선, 제목, 분류. 다크 모드를 따른다. 바깥 모서리는 런처(One UI)가 크게 둥글게 자르므로 앱에서 정할 수 없다.
  - 받아 둔 파일만 읽으므로 인터넷이 없어도 그린다. 알림 예약을 다시 할 때(발송 기록·알림 시각·알린 날이 바뀔 때) 함께 다시 그리고, 알림 시각과 자정에 다시 그리도록 알람을 하나 걸어 둔다.
  - 설정 > 앱 > 홈 화면 위젯 · 놓기로 홈 화면에 놓을 수 있다 (시스템이 놓을지 묻는다).

## 7. 만들기와 설치

- 기술은 [GithubWidget](../../GithubWidget)과 같게 간다: Kotlin, Jetpack Compose (Material 3), WorkManager, AlarmManager. 빌드 도구 버전도 맞춘다.
- 여기에 Firebase (Auth, Firestore)를 더한다 (3단계).
- 패키지 이름(applicationId): `com.maeilmail.app`. Firebase에 등록하면 바꾸기 어렵다.
- 마크다운은 앱 안의 WebView에서 웹과 같은 `marked` 15.0.12와 `Prism` 1.29.0으로 그린다. 파일은 앱에 넣어 두었다 (`docs/THIRD_PARTY.md`).
- 빌드: `JAVA_HOME`을 Android Studio에 들어 있는 JDK(`C:/Program Files/Android/Android Studio/jbr`)로 두고 `gradlew assembleDebug`. 설치는 `adb install --user 0 -r` (듀얼 앱 사용자에게 설치하지 않는다).
- Play 스토어에 올리지 않는다. USB 디버깅으로 설치하고 업데이트한다. debug 키로 서명한다.
- 앱 이름은 "매일메일". 아이콘은 후보 3개(지면, 편지, 점과 줄) 중 "점과 줄"로 정했다 (2026-11-22): 흰 바탕에 웹 상단 바의 초록 각진 점과 문서 제목 줄 두 개. 테마 아이콘(단색)과 알림 표시줄 아이콘도 같은 모양이다.
- 코드 저장소: https://github.com/YeongGyu1110/maeil-mail-reborn-app (공개)
